### 2.2 Cloudflare zone — Sys Admin territory

Nothing in this repo can set or override these. Document, request, then **verify against the live
response** — never assume a toggle was flipped.

| #   | Action                                                                                              | Verify with                                                                              | Status |
| --- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------ |
| Z1  | Confirm the AI-crawler managed rule is **not** blocking the retrieval bots `app/robots.ts` allows   | `curl -sS -H 'Cache-Control: no-cache' "https://hambabait.co.il/robots.txt?cb=1"`        | ✅     |
| Z2  | Confirm the Browser Cache TTL override is not defeating `public/_headers` on `/_next/static/*`      | `curl -sSI https://hambabait.co.il/_next/static/css/<hash>.css \| grep -i cache-control` | ✅     |
| Z3  | Record which security headers are zone-level (present on the apex, absent on `hambabait.pages.dev`) | `curl -sSI` on both hosts, diffed                                                        | ✅     |

**All three verified live on 2026-08-31, immediately after the deploy.**

- **Z1 ✅** The live `/robots.txt` serves our own allow list — `OAI-SearchBot`, `ChatGPT-User`,
  `Claude-User`, `Claude-SearchBot`, `PerplexityBot`, `Perplexity-User`, `GPTBot`, `ClaudeBot`,
  `Google-Extended` … **Cloudflare is not prepending a managed AI-crawler block.** This is the
  condition that silently broke across this fleet until 2026-08, so **re-check it after any zone
  change** — nothing in the repo can detect it.
- **Z2 ✅** `Cache-Control: public, max-age=31536000, immutable` on
  `/_next/static/css/5e3bd2b50426893d.css`. **`public/_headers` is winning; the zone's 4-hour
  Browser Cache TTL is not overriding it.** No zone fix needed.
- **Z3 ✅** Zone-level headers observed on the apex:

  | Header                      | Value                                      |
  | --------------------------- | ------------------------------------------ |
  | `Strict-Transport-Security` | `max-age=15552000` (180 days)              |
  | `X-Frame-Options`           | `SAMEORIGIN`                               |
  | `X-Content-Type-Options`    | `nosniff`                                  |
  | `Referrer-Policy`           | `strict-origin-when-cross-origin`          |
  | `Permissions-Policy`        | `geolocation=(), microphone=(), camera=()` |

  The repo adds exactly one header of its own: `Content-Security-Policy-Report-Only`. There is **no
  duplicate and no collision** — the zone sets no CSP.

  > **Remaining zone question (not blocking):** HSTS is 180 days with **no `includeSubDomains` and
  > no `preload`**. Raising it to a year with both is the conventional hardening, but `preload` is
  > effectively irreversible — it belongs to the owner, and only once every subdomain is known to
  > be HTTPS-only.

## 3. What we are NOT asking for, and why

So nobody helpfully supplies these:

- **Review text or testimonials to publish.** Reviews must be left by real customers on a platform
  where they can be checked. We will never write, seed, incentivise or filter them.
- **A stock photo of a technician.** That is a staffing claim rendered as an image.
- **A "good enough" number for years in business.** Either the real one or none.
- **Permission to publish the phone number to directories before Q1 is answered.** Waiting is
  cheaper than unwinding.
